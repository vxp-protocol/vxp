Experimental

What draft 0.1 declares experimental

The native profile. /.well-known/vxp.json (with "status": "experimental" in the document) and the endpoints under /v1 (specification §8). With them, an agent that speaks neither Poppy nor PACT runs the whole cycle: discover, identify itself with private_key_jwt and DPoP, receive per-request authority with authorization_details, ask, receive a proposal, accept, follow events, cancel, get the proof and keep the relationship. It passes its tests in process and over the network. Adoption by a third-party agent is pending.

Native-only gateway. The native profile needs neither adapter. The reference implementation runs that way with both adapters off, and a test runs the whole cycle with an agent that signs with plain node:crypto, checked by the independent verifier anchored by the issuer alone (specification §8). No agent outside SOVRAS has used it yet.

VXP Relationship over HTTP. Querying and revoking a relationship (R10, R11) and the HTTP inbox (R2, R7) use native profile routes, so they share its maturity. The path over a Poppy conversation (§7) is the one a live personal agent ran, once, through the Poppy adapter.

A company may publish vxp.json, poppy.json and the PACT Agent Card at the same time, with the same issuer, authorization server and metadata. An agent that speaks Poppy or PACT does not need the native profile.

Pending

What is pending

The open items of specification §13, with their detail.

  1. Real agents

    On 21 October, personal agents went through the Poppy adapter with temporary identities, among them Nova, the personal agent SOVRAS uses internally, and a third-party web agent, Grok, went through the companies' web pages. Still missing: a third-party agent on the Poppy adapter, the PACT adapter or the native profile, and an agent with a stable identity.

  2. External counterpart for the two-way relationship

    Run once with a live personal agent over a Poppy conversation (§7). No agent outside SOVRAS's own runs has used this path yet, and no third party implements the HTTP inbox of R2.

  3. Independence of the evidence

    • There are no external witnesses of the log.
    • The operator holds the company's key.
    • There is no second independent issuer.
    • Until these exist, VXP Proof is an attestation by the operator, and its evidence depends on SOVRAS.

  4. Approval through the company's channel in the native profile and in Poppy

    Today it is agent_asserted. company_channel exists in PACT and on the company's approval pages (approve, change, authorize), run with Grok.

  5. Real channels

    Meta's WhatsApp integration, real voice, and account linking without WhatsApp. Web Bot Auth was verified live with the signature of a real crawler.

  6. Production

    • State lives in memory. Proof keys persist across restarts since 22 October 2026 (§10, key rotation).
    • There are rate limits per client type and a cap on codes per number (active in the public sandbox); real anti-SSRF DNS protection is missing.

  7. Independent review

    Nobody has yet independently reviewed VXP Relationship, the channels, or the changes to VXP Proof in this draft.

  8. Poppy draft 0.2, a subset

    Not implemented: the person's direct conversation with the company (Poppy §7.10), streaming, DPoP nonce, web browsing with a shared session, OpenAPI and MCP, Direct Sign-In and Mediated Sign-In, and a screen where the person sees and disconnects their agents. Poppy may break compatibility before 1.0.

  9. Protocol domain

    vxpprotocol.org was registered on 22 October 2026 and is under SOVRAS's control, so the extension identifiers use a domain the publisher controls, as Poppy requires. This site, the documents and the repository are published there since 23 October 2026.

  10. Evidence for the operations of 21 October

    Two operations have no saved proof, the keys lived in memory (only OP-5 was re-verified with signatures, on 22 October; its package carries earlier test data and is available on request) and none was anchored. The reference implementation now keeps its keys persistent, so later runs save each proof with material that can be checked again.

  11. Conformance by a third party

    The conformance validator exists (conformance/): it acts as a personal agent against any native endpoint and reports each check with its rule. Nobody outside SOVRAS has run it against their own implementation yet (Conformance).

Incompatible changes

Identifiers renamed from the 0.1 annex

VXP is independent of SOVRAS. The protocol identifiers that the 0.1 annex named with «sovras» are used as follows from 22 October 2026. A proof signed with the earlier names does not verify with the current verifier. Paths for keys, log and bundles are each implementation's own, discovered through the issuer metadata (specification §8, implementation paths); the reference implementation moved its own from /sovras/ to /vxp/ on 22 October and still answers at the old ones.

History

Versions of draft 0.1

  1. 23 Oct 2026

    Revision of the specification and release candidates 0.1.0-rc.2 to 0.1.0-rc.4 of the repository.

    • Editorial review of the site, the documentation and the specification against the code: the scope of one execution (I2, O6), the role of resource, approval of a revision, Relationship over Poppy, the errors a client meets, and key rotation stated precisely. The verifiers now say whether the keys were fetched or read from saved material (key_source).
    • Personal-agent library: a URL a company gives is accepted only in canonical form; under PACT, the interface that receives the delegation must be on the authorization server's origin.
    • Native endpoints: read capabilities answered at once, without a request or a proof; approved_by and user_approval_required stated, with standing_permission recorded in the approval.
    • JSON Schemas for every object of the draft, checked against real runs and by the conformance validator.
    • Documentation, conformance validator and personal-agent tools (library, CLI, MCP server, optional Poppy and PACT adapters) in the repository.
  2. 22 Oct 2026, evening

    Second revision of the specification that day.

    • Two public components, VXP Proof and VXP Relationship, and operation requirements O1 to O7: required behavior with no interface, kept apart from the evidence that shows it and from each implementation's internal controls.
    • Native-only gateway: VXP implemented with the native profile alone, without Poppy or PACT.
    • Implementation paths: only the well-known locations and the native endpoints are fixed; every other path is discovered through the metadata.
    • Reading a verdict, key rotation and historical verification.
    • Three classes of tests kept apart in conformance.
  3. 22 Oct 2026

    First revision of the specification that day.

    • Protocol identifiers renamed to vxp (table above).
    • Interoperability rule I1 made precise: inside an adapter, VXP keeps the external contract literally; the native profile lives beside the adapters on the same issuer.
    • The rules where a request becomes an operation written as behavior with no endpoint; that evening they became the operation requirements O1 to O7.
    • Conformance with Poppy draft 0.2 §4.4: expanding permissions grants only what was requested.
    • Every figure reconciled with a run logged that day. Figures from earlier days without a log were replaced.
  4. 21 Oct 2026

    Specification consolidated as VXP draft 0.1, on top of the 0.1 annex: VXP Relationship and VXP Proof as public contracts, the native profile as experimental, and adapters for Poppy and PACT. The same day, personal agents through the Poppy adapter, among them Nova, the personal agent SOVRAS uses internally, and a third-party web agent, Grok, operated in SOVRAS's production with customers, first on SOVRAS's own resources.
