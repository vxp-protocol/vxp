Experimental

What draft 0.1 declares experimental

The native profile. /.well-known/vxp.json (with "status": "experimental" in the document) and the endpoints /v1/requests, /v1/proposals/{id}/accept|counter, /v1/requests/{id}/cancel|events|proof and /v1/relationships/{id}. With them, an agent that speaks neither Poppy nor PACT runs the whole cycle: discover, identify itself with private_key_jwt and DPoP, receive per-request authority with authorization_details, ask, receive a proposal, accept, follow events, cancel, get the proof and keep the relationship. It passes its tests in process and over the network. Adoption by a third-party agent is pending.

VXP Relationship over HTTP. Querying and revoking a relationship (R10, R11) and the HTTP inbox (R2, R7) use native profile routes, so they share its maturity. The path over a Poppy conversation (§3.4) is the one a running agent, Nova AI, has run.

A company may publish vxp.json, poppy.json and the PACT Agent Card at the same time, with the same issuer, authorization server and metadata. An agent that speaks Poppy or PACT does not need the native profile.

Pending

What is missing, stated as missing

Section 12 of the specification, in full.

  1. Real agents

    SOVRAS's own personal agent in beta (Nova AI) operated live through the Poppy adapter, with temporary identities, and one third-party web agent (Grok) operated through the web. Still missing: a third-party agent on the Poppy adapter, the PACT adapter or the native profile, and an agent with a stable identity. ChatGPT agent was not tested live.

  2. External counterpart for the two-way relationship

    Run with Nova AI, SOVRAS's own agent, over the path of §3.4. A third-party agent on this path, and a third party implementing the HTTP inbox of R2, are still missing.

  3. Independence of the evidence

    • There are no external witnesses of the log.
    • The operator holds the company's key.
    • There is no second independent issuer.
    • Until these exist, VXP Proof is an attestation by the operator, and its evidence depends on SOVRAS.

  4. Approval through the company's channel in the native profile and in Poppy

    Today it is agent_asserted. company_channel exists in PACT and on the company's approval pages (approve, change, authorize), run with Grok.

  5. Real channels

    Meta's WhatsApp integration, real voice, and account linking without WhatsApp. Web Bot Auth was verified live with the signature of a real crawler.

  6. Production

    • State lives in memory.
    • There are rate limits per client type and a cap on codes per number (active in the public sandbox); real anti-SSRF DNS protection is missing.
    • Nothing has been built yet in the SOVRAS platform repository, and a known gap in its policy layer remains open.

  7. Independent review

    Five review rounds examined the 0.1 specification and left corrections; none closed as an approval without observations. Nobody has yet independently reviewed VXP Relationship, the channels, or the changes to VXP Proof in this draft.

  8. Poppy draft 0.2, a subset

    Not implemented: the person's direct conversation with the company (Poppy §7.10), streaming, DPoP nonce, web browsing with a shared session, OpenAPI and MCP, Direct Sign-In and Mediated Sign-In, and a screen where the person sees and disconnects their agents. Poppy may break compatibility before 1.0.

  9. Protocol domain

    vxpprotocol.org was registered on 22 October 2026 and is under SOVRAS's control, so the extension identifiers use a domain the author controls, as Poppy requires. Still to do: publish this site and the documents on that domain.

  10. Evidence for the operations of 21 October

    Two operations have no saved proof, the keys were ephemeral (only OP-5 was re-verified with signatures, on 22 October; its package carries earlier test data and is available on request) and none was anchored. The next runs must use persistent keys and save each proof with its material and its verdict.

  11. License

    Apache 2.0 is the proposed license; the LICENSE file is still missing from the repository to be published.

  12. Relationship over HTTP and the native profile

    Querying and revoking the relationship (R10, R11) and the HTTP inbox (R2, R7) use routes of the native profile, which is experimental: VXP Relationship over HTTP has that same maturity. The path over the Poppy conversation (§3.4) is the one a running agent, Nova AI, ran.

Incompatible changes

Identifiers renamed from the 0.1 annex

VXP is independent of SOVRAS. The protocol identifiers that the 0.1 annex named with «sovras» are used as follows from 22 October 2026. A proof signed with the earlier names does not verify with the current verifier. Paths of the reference implementation, such as /sovras/log/, belong to SOVRAS as operator and are outside the protocol.

History

Versions of draft 0.1

  1. 22 Oct 2026

    Revision of the specification.

    • Protocol identifiers renamed to vxp (table above).
    • Interoperability rule I1 made precise: inside an adapter, VXP keeps the external contract literally; the native profile lives beside the adapters on the same issuer.
    • Capability Gate written as a behavior contract with no endpoint.
    • Conformance with Poppy draft 0.2 §4.4: expanding permissions grants only what was requested.
    • Every figure reconciled with a run logged that day. Figures from earlier days without a log were replaced.
  2. 21 Oct 2026

    Specification consolidated as VXP draft 0.1, on top of the 0.1 annex: VXP Relationship and VXP Proof as public contracts, the native profile as experimental, and adapters for Poppy and PACT. The same day, SOVRAS's own personal agent in beta (Nova AI) and one third-party web agent (Grok) operated against test companies configured in SOVRAS.
