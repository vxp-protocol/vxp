Context for everything on this page

  • The companies are test companies configured in SOVRAS: a hardware store and a hotel, with fictitious names. Their inventory, payments and WhatsApp line are simulated. On the WhatsApp line, the operator reads the one-time code.
  • The agents in section c are running personal agents: Nova AI (SOVRAS's personal agent, beta) and one third-party web agent, Grok. Their decisions were their own.
  • No operation was anchored in a public log. A Rekor entry exists for an earlier test log, from before all of these operations.
  • Re-verified with signatures: OP-5 from 21 October, re-verified on 22 October, and the two operations of the native run captured on 22 October. The other proofs were signed with ephemeral keys from test servers that no longer run.
  • On this page, customers appear as Customer A and Customer B, and phone numbers, addresses, IP addresses, codes and the agents' tunnel hosts are left out. Downloaded proofs keep their signed content unchanged.

Reply recorded as a server event · the signed reply receipt and the signed agreement were written into the Poppy conversation and not saved · the company's signed message was saved, and its key no longer exists, so its signature cannot be checked today · its signed summary carries an encoding error (U+FFFD in place of «í»)

On the web operations (OP-3, OP-5, OP-6, OP-8). company_channel shows that the code sent to the customer's registered number was used. In OP-6 and OP-8, the requests to the authorization page carry the same user agent as the chat, so the evidence does not show that a person saw the page.

Payments. Only the hotel made simulated pre-authorizations. The store's orders recorded no charge.

No agent used PACT or the native profile on 21 October. The access log of the hotel session has no /a2a or /v1 request from an agent.

d · Future scenarios

Scenarios that have not been executed

Each is pending in the specification (Status). They describe what the protocol allows; none has run with a third party.

Not executednative profile

A third-party agent on the native profile

An agent that speaks neither Poppy nor PACT discovers vxp.json, receives per-request authority, operates and gets the proof. Today only SOVRAS's test agent has run this cycle.

Not executedVXP Relationship over HTTP

A company proposal to the agent's own inbox

The company signs a proposal and delivers it to an inbox_uri the agent publishes; the person approves and the agent accepts. Today tested only with SOVRAS's own inbox.

Not executedPACT adapter

A PACT agent from outside SOVRAS

A third-party PACT agent delegates by device code, operates, and receives both its PACT receipt and the VXP proof bound to it.

Not executedrelationship over PACT

A relationship carried over A2A

The company-initiated request travelling over PACT. Its specification and tests are still to be written.

Not executedVXP Proof

A proof that does not rest on the operator alone

An operation with persistent keys, its proof anchored in a public log with external witnesses and a second independent issuer, so the verifier can derive more than an operator attestation.
