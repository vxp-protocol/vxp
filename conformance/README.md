# VXP conformance

Tools to check that an implementation of the VXP native profile behaves as the specification requires.

| File | What it is |
|---|---|
| `validate.ts` | The validator. It acts as a personal agent against a company's server and reports every check with the rule it tests. |
| `CHECKLIST.md` | What the validator cannot see, to check by hand. |
| `MATRIX.md` | Every normative rule, with the reference tests, validator checks and other evidence that cover it. Generated by `matrix.ts` from `matrix.json`. |
| `reference/` | Runs the validator against this repository's reference implementation, with two test aids that only the reference has. |

Requirements: Node.js 22.18 or newer. No dependencies.

## Run it against the reference implementation

```sh
node conformance/reference/run.ts --report conformance-report.json
```

It starts the reference implementation as a native-only gateway (no Poppy, no PACT) on port 3740 with
persistent keys in a temporary directory, serves the validator's agent on port 3890, and runs every check.
Expected summary: `{"pass":50,"fail":0,"optional":0,"manual":3,"skipped":0}`. It writes
`conformance-report.json` and `conformance-report.md`.

## Run it against your implementation

Write a config file:

```json
{
  "domain": "agents.your-company.example",
  "agentOrigin": "https://validator.your-company.example",
  "agentPort": 3890,
  "operation": { "operation": "order.reschedule_delivery", "target": { "order_ref": "A-100" }, "parameters": { "delivery_date": "2026-11-02" } },
  "counter": { "proposed_terms": { "delivery_date": "2026-11-03" } },
  "relationship": { "actions": ["order.propose_change"], "limits": { "max_per_day": 2, "duration_seconds": 3600 } },
  "approve": "manual",
  "companyRequest": { "command": "./start-company-request.sh", "proposalAction": "order.propose_change" }
}
```

```sh
node conformance/validate.ts my-config.json --report my-report.json
```

| Field | Meaning |
|---|---|
| `domain` | The host that serves `/.well-known/vxp.json`. `scheme` defaults to `https`; use `"http"` only locally. |
| `agentOrigin`, `agentPort` | The validator serves its agent's Client ID Metadata Document (`/agent.json`), JWKS (`/jwks.json`) and inbox (`/vxp/inbox`) on `agentPort`. Your server must reach them at `agentOrigin`: put an HTTPS tunnel or proxy in front of the port. |
| `operation` | A write operation you publish in `vxp.json`, on a resource your test account owns. |
| `counter` | Optional. A counter-proposal your server should accept for that operation. Without it, the counter checks are reported `optional`. |
| `relationship` | Optional. The relationship actions to ask for in the same consent. Without it, or if your metadata has no `vxp_relationship`, the relationship checks are `optional`. |
| `approve` | How the person approves the device authorization. `"manual"` prints the verification URL and waits while you approve as the test customer. Or `{ "command": "…" }`: it runs with `VXP_VERIFICATION_URI`, `VXP_USER_CODE` and `VXP_SCOPE` and must return once approved. |
| `companyRequest` | Optional. Starting a request inside a relationship is a company action the agent cannot trigger. The command runs with `VXP_RELATIONSHIP_ID`, `VXP_ACTION`, `VXP_KIND` (`proposal` or `question`) and, after revocation, `VXP_EXPECT_REFUSAL=1`. Without it, those checks are `skipped`. Add `questionAction` to check closed questions (R17). |

## Statuses

| Status | Meaning |
|---|---|
| `pass` | The requirement held. |
| `fail` | The requirement did not hold. The exit code is 1. |
| `optional` | An optional capability your server does not offer, or that you did not configure. |
| `manual` | It cannot be checked from outside; see `CHECKLIST.md`. |
| `skipped` | A step it depends on could not run. |

Every check names the rules it tests, linked to the specification. The proof is verified with the independent
browser verifier (`../verifier/vxp-verify.js`), anchored by the issuer, never by a document your server hands over.

## What this is not

A report from this validator is your own evidence that your implementation behaves as specified on the
paths it exercised. It is not a certification. The validator covers the native profile. For the Poppy and
PACT adapters, use those protocols' own official tools.
