Open protocol · draft 0.1

What the agent asked. What the person approved. What the system did.

VXP is an open protocol for work that agents do for people inside companies. It decides what an agent may do, keeps an authorized relationship that either side can start, and leaves signed proof checked against the company's own system.

Read the specification Verify a proof

Native profile: experimentalAdapters for Poppy draft 0.2 and PACT 1.0Apache 2.0, proposed

Where it comes from

Three questions every operation leaves behind

SOVRAS builds agents that change orders, deliveries and reservations inside companies' systems. After each of those operations, someone eventually asks the same three questions. When the request comes from a person's own agent, the company did not build that agent and cannot see its conversation, so the answers have to travel with the operation. VXP writes them into the protocol.

  1. 1Who asked, and on whose behalf?
  2. 2Which exact terms did the person approve, and through which channel?
  3. 3What did the company's system actually record afterwards?

    Two questions
    
			
    What it allows, and what it depends on
    
		
    
		
    
			
    
				
    What can a personal agent do with a company that implements VXP?
    
				
      
					
    • Find the company and read what it offers.
      • 
					
    • Identify itself and say which person it acts for.
      • 
					
    • Receive permission for one specific operation, and ask for more when it needs it.
      • 
					
    • Ask, negotiate and receive a proposal with exact terms.
      • 
					
    • Have the person approve those terms, then see the operation run once.
      • 
					
    • Receive a signed record of what the company's system shows afterwards.
      • 
					
    • Answer when the company asks something within an agreement the person approved.
      • 
				
    
			
    
			
    
				
    Can a company implement VXP without Poppy, PACT or the SOVRAS platform?
    
				
    
					
    The specification
    Yes. VXP has its own profile for discovery, authorization, operations, proof and relationships. Poppy and PACT are optional adapters.
    
					
    An implementation today
    The reference implementation by SOVRAS, to be published under Apache 2.0 with the verifier, the test vectors and the conformance kit.
    
					
    Maturity
    The native profile is experimental: it passes its tests, and no third-party agent uses it yet. On 21 October, SOVRAS's own personal agent in beta (Nova AI) entered through the Poppy adapter, and one third-party web agent (Grok) through the web.
    
				
    
			
    
		
    
	
    

    


    
	
    
		
    
			
    What VXP defines
    
			
    Three capabilities of its own
    
		
    
		
    
			
    
				
    Capability Gate
    
				
    A valid identity is a starting point. What runs is the intersection of what the person delegated, what the company allows and what the resource admits. VXP defines these as rules any implementation must enforce, with no endpoint of its own.
    
				
    Owner = (profile, client_id, sub, account). One execution per resource. No read-back, no succeeded.
    
			
    
			
    
				
    Relationship
    
				
    With an agreement the person approved, the company can start a request toward the person's agent: confirm or block a dispatch, keep or release a booking. The agreement names its actions, daily limit and expiry, and ends when the delegation is revoked.
    
				
    Signed agreement vxp-relationship+jwt, signed request, signed reply receipt.
    
			
    
			
    
				
    Proof
    
				
    A chain of signed statements that binds the exact terms, the approval and its channel, the execution, what the company's system showed afterwards and the result. When the outcome is unknown, the chain says unknown.
    
				
    The verifier derives the assurance level. Today it reports one root of trust: the operator.
    
			
    
		
    
	
    

    


    
	
    
		
    
			
    Entry paths
    
			
    Its own profile first, then adapters
    
			
    A company can publish the native profile and the adapters at the same time, on the same issuer. An agent that already speaks Poppy or PACT does not need the native profile.

    Demonstrations
    
			
    Run with real personal agents
    
			
    On 21 October 2026, SOVRAS's own personal agent in beta (Nova AI) and one third-party web agent (Grok) operated against a hardware store and a hotel configured in SOVRAS for these tests. Inventory, payments and the WhatsApp line were simulated. The agents and their decisions were real.
